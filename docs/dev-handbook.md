# Local Development Handbook (From 0 to Running)

This guide explains how **`mise`** manages the entire `headscale-panel` workspace and walks you through starting a complete local development environment from scratch.

> [!NOTE]
> This handbook assumes a **Linux** development machine by default (all scripts, Docker mounts, and `/dev/net/tun` target Linux). If you are on macOS or Windows (WSL2), adapt the environment accordingly.

---

## 1. What `mise` Manages in This Repository

1. **Runtime Toolchains (`[tools]`)**
   - Pins and installs Go, Node.js, and pnpm; see `[tools]` in the root [`mise.toml`](../mise.toml) for the exact versions.
2. **Shared Environment Variables (`[env]`)**
   - `PROJECT_ROOT`, `BACKEND_DIR`, `FRONTEND_DIR`, `SHELL_DIR`, `DEV_DATA_DIR` (`<repo>/dev-data`, git-ignored), and `HS_REPO_URL`.
3. **Modular Task Orchestration (`[tasks.*]`)**
   - Every shell workflow is split into small, single-responsibility scripts under `shell/{lib,dev,hs,certs}` and invoked exclusively through `mise run <task>`.

### Task Reference

| Namespace | Key Tasks | Purpose |
| --- | --- | --- |
| **Backend** | `backend:dev`, `backend:build`, `backend:vet`, `backend:tidy` | Run, build, vet, and tidy the Go backend |
| **Frontend** | `frontend:install`, `frontend:dev`, `frontend:build`, `frontend:check`, `frontend:lint`, `frontend:lint:fix` | Install deps, run Vite dev server, type-check, lint, and build the React SPA |
| **Aggregate** | `check`, `build`, `build:docker` | Full CI quality gate (`backend:vet` + `frontend:check` + `frontend:lint` + `hs:check-drift`) and full artifact/Docker builds |
| **Dev Stack (Release Image)** | `dev:up`, `dev:up:host`, `dev:up:fresh` | Standard mode targeting the latest released Headscale image (e.g. `ghcr.io/juanfont/headscale:0.30.0`) |
| **Dev Stack (Source Build)** | `dev:up:source`, `dev:up:host:source`, `dev:up:fresh:source` | **Temporary mode** for unreleased Headscale commits: builds `headscale-panel-dev/headscale:<short-sha>` from `AdaptedHeadscaleCommit` via Docker before starting |
| **Dev Lifecycle** | `dev:verify`, `dev:logs`, `dev:down`, `dev:down:volumes`, `dev:reset` | Verify tailnet isolation/routing, inspect logs, stop, or wipe `dev-data/` + volumes |
| **Dev Sub-modules** | `dev:check-deps`, `dev:prepare`, `dev:clean-hs-state`, `dev:ensure-hs-image`, `dev:build-panel`, `dev:start`, `dev:bootstrap:{apikey,identities,clients,panel}` | Individual composable steps behind `dev:up*` |
| **Upstream Headscale** | `hs:diff`, `hs:vendor-spec`, `hs:check-drift`, `hs:build-image` | Track upstream API/config diffs, vendor OpenAPI 3.0.3 specs, enforce baseline alignment, and build local images |
| **TLS Certs** | `certs:self-signed`, `certs:private-ca` | Generate self-signed or private-CA certificates into `dev-data/cert/` |

## 2. Where Local Dev Data Lives

All runtime files generated by the local dev stack are stored in the root **`dev-data/`** directory:

```text
dev-data/
├── headscale/
│   ├── etc/config.yaml         # Seeded from shell/docker/dev/headscale/config.main.yaml.tpl
│   └── lib/                    # Headscale SQLite DB, noise key, extra-records.json
├── panel/                      # Panel SQLite DB and RS256 signing keys
├── influxdb/                   # InfluxDB 2 time-series storage
├── state/                      # api-key.env and preauth.env minted during bootstrap
└── cert/                       # Optional TLS certs from mise run certs:*
```

Running `mise run dev:reset` cleanly removes containers, Docker volumes, and `dev-data/`.

## 3. From 0 to a Running Local Environment

### Step 1: Install Prerequisites
- **Docker** (20.10+ with `docker compose` plugin) and `/dev/net/tun` available.
- **`mise`**: https://mise.jdx.dev/getting-started.html
- **`jq`** and **`openssl`** (used by `dev:verify` and `certs:*`).

### Step 2: Trust Config & Install Toolchains
```bash
git clone <repo-url> headscale-panel
cd headscale-panel
mise trust mise.toml
mise install
mise run frontend:install
```

### Step 3: Verify Codebase Health
```bash
mise run check
```

### Step 4: Start the Dev Tailnet Stack

Choose **Mode A** (default, when a released Headscale `0.30.x` image is published) or **Mode B** (temporary source-build mode while Headscale `0.30.0` is still unreleased):

#### Mode A — Standard Release Image (Containerized Panel)
```bash
mise run dev:up
```

#### Mode B — Temporary Source-Build Mode (Unreleased `0.30.0-dev`)
```bash
mise run dev:up:source
```

This builds `headscale-panel-dev/headscale:<commit>`, builds the panel container, starts Headscale + InfluxDB + 2 isolated Tailscale clients (`client-a`, `client-b`) + 2 target nginx servers (`target-a`, `target-b`), mints an API key, creates `alice` and `bob`, joins both clients, and initializes the panel admin account (`admin` / `dev-admin-password-1234`).

#### Mode C — Host Hot-Reload Mode (For Active Frontend/Backend Coding)
```bash
# 1) Start Headscale, InfluxDB, and Tailscale clients in Docker
mise run dev:up:host:source   # or `mise run dev:up:host` for release image

# 2) In terminal 2: start Go backend
mise run backend:dev

# 3) In terminal 3: start Vite frontend with HMR
mise run frontend:dev
```

### Step 5: Verify Tailnet Routing & Open the Panel
```bash
mise run dev:verify
```
When all 6 assertions pass, open:
- **Panel UI (container mode)**: `http://localhost:8090/panel`
- **Panel UI (host Vite mode)**: `http://localhost:5173/panel`
- **Headscale HTTP API**: `http://localhost:5080`
- **Default Dev Credentials**: `admin` / `dev-admin-password-1234` (configured in `shell/docker/dev/.env`)

### Step 6: Daily Commands
```bash
mise run dev:logs          # Follow container logs
mise run dev:down          # Stop containers (keep dev-data/ and volumes)
mise run dev:reset         # Wipe containers, volumes, and dev-data/
```
